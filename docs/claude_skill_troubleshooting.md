- **목표**: 윈도우 환경에서 Claude Code 커스텀 스킬을 맥(macOS)과 동일하게 쾌적하고, 심지어 데이터 유실 위험 없이 더 안전하게 관리하는 궁극의 세팅 구축.

  1. 윈도우 **개발자 모드 활성화** (심볼릭 링크 자동화로 플러그인 호환성 확보)

## 2. 발생했던 두 가지 에러와 원인 분석 (Mac vs Windows 구조 분석)

과거 발생했던 2가지 에러는 각각 다른 원인(운영체제 차이 vs 파일 이동)을 가지고 있었습니다.

### 🚨 에러 1: 윈도우 심볼릭 링크(거울) 생성 권한 문제
- **상황**: `skill-creator`로 만든 스킬이 Claude에 전혀 인식되지 않음.
- **원인 분석**:
  - **맥(macOS) 튜토리얼**: 시스템 권한 없이도 심볼릭 링크(거울)가 자유롭게 생성됨. `/skill-creator`가 '플러그인 폴더'에 스킬 원본을 생성하더라도, 거울을 통해 전역 폴더(`~/.claude/skills/`)에서 즉시 비춰주기 때문에 정상 인식됨.
  - **윈도우(Windows)**: 관리자 권한이 없으면 링크 생성이 조용히 차단됨. 원본 파일은 생성되었지만 거울이 안 만들어져서 스킬을 찾지 못함.
- **해결책**: 윈도우 **설정 > 시스템 > 개발자용 > 개발자 모드 켬**. 
  - 이제 윈도우도 맥처럼 즉각적인 심볼릭 링크 생성이 가능해짐.

### 🚨 에러 2: `marketplace.json` 경로 꼬임 문제 (안전을 위한 이사 과정)
- **상황**: `/plugin` 명령어 실행 시 경로 탐색 실패 에러 발생.
- **원인 분석**:
  - `/skill-creator` 도구는 공식 플러그인(`example-skills`) 소속이기 때문에, 새 스킬을 만들면 **자기네 플러그인 폴더에 원본을 저장**하고 자기네 주소록(`marketplace.json`)에 이름을 등록함.
  - **맥 튜토리얼의 치명적 단점 (시한폭탄)**: 맥 튜토리얼은 스킬을 위험한 플러그인 폴더 안에 그대로 방치함. 만약 공식 플러그인이 업데이트되면 새 버전으로 덮어씌워지면서 **내가 만든 커스텀 스킬 원본이 통째로 날아감.**
  - **오류 발생 이유**: 사용자가 이 위험을 직감하고 원본 스킬을 안전한 독립 구역(`~/.claude/skills/`)으로 **수동 이동(이사)**시킴. 파일 본체는 플러그인 업데이트의 폭격으로부터 안전해졌지만, 이전 집 주소록(`marketplace.json`)에 옛날 주소로 이름이 남아 있어 경로 탐색 에러가 발생한 것.
- **해결책**: `marketplace.json` 파일을 열어 옛날 주소로 적힌 스킬 이름 2줄을 지워주어 깔끔하게 해결.

## 3. 완벽한 커스텀 스킬 관리 원칙 (궁극의 세팅)

맥(macOS) 튜토리얼보다 훨씬 더 근본적이고 안전한 환경을 위해, AI 에이전트의 전역 규칙(`GEMINI.md`)을 활용하여 아래와 같은 최종 규칙을 확립했습니다.

### 글로벌 커스텀 룰 (`.gemini/GEMINI.md` 14번째 줄 적용 완료)
```markdown
커스텀 스킬을 새로 생성하거나 스킬 생성 도구(/skill-creator 등)를 사용할 때는 반드시 전역 스킬 경로(C:\Users\kch27\.claude\skills\) 하위에 직접 폴더를 생성하고, 어떤 경우에도 기존 플러그인 폴더나 marketplace.json 파일을 수정하지 마세요.
```

### 🏆 이 세팅이 완벽한 3가지 이유
1. **타 플러그인 호환성**: 개발자 모드를 켰기 때문에, 앞으로 남들이 만든 훌륭한 공식 플러그인을 다운받을 때는 심볼릭 링크(거울)를 통해 맥처럼 문제없이 깔끔하게 설치 및 작동합니다.
2. **내 스킬의 절대 안전 보장**: 내가 `/skill-creator`로 새로 생성하는 스킬은 `GEMINI.md` 규칙에 의해 위험한 플러그인 폴더를 거치지 않습니다. 100% 안전한 내 전용 금고(`~/.claude/skills/`)에 물리적으로 직접 꽂아 넣습니다.
3. **에러 원천 차단**: 플러그인 폴더를 전혀 건드리지 않으므로, 플러그인 업데이트로 인한 **원본 삭제 위험이 0%**이며, 주소록(`marketplace.json`) 꼬임 에러 발생 확률도 **0%**입니다.

## 4. Claude Code(터미널) 전용 스킬 생성기 구축 (`/my-skill-creator`)

위에서 설정한 `GEMINI.md` 규칙은 Antigravity 환경에서만 동작하는 룰입니다. 따라서 터미널에서 Claude Code(`claude`)를 직접 실행하고 공식 `/skill-creator`를 부르면, 다시 플러그인 폴더에 스킬을 저장해버리는 치명적인 에러(시한폭탄)가 반복됩니다. 이를 터미널 환경에서도 원천 차단하기 위해 **나만의 전용 스킬 생성기**를 추가로 구축했습니다.

### 구축 방법 및 원리
- **위치**: `C:\Users\kch27\.claude\skills\my-skill-creator\SKILL.md`
- **핵심 프롬프트(규칙)**: 
  > "무조건 `~/.claude/skills/` 전역 경로 하위에 직접 스킬을 저장하고, `marketplace.json`이나 플러그인 폴더는 절대 건드리지 마라."
- **효과**: 이 규칙이 하드코딩된 나만의 도구를 사용함으로써, 터미널(Claude Code) 안에서도 100% 안전하게 스킬을 찍어낼 수 있습니다.

### 터미널 사용법
터미널에서 `claude`를 실행한 뒤, 기존의 위험한 공식 생성기 대신 아래와 같이 내 전용 생성기를 호출합니다.
```text
/my-skill-creator [만들고 싶은 스킬 설명]
```

## 5. 최종 투트랙(Two-track) 스킬 관리 시스템

이제 어떠한 충돌이나 에러 없이 완벽하게 스킬을 관리할 수 있는 투트랙 시스템이 완성되었습니다.

1. **남이 만든 '공식 플러그인'을 쓸 때** (예: `claude plugin add ...`)
   - **그냥 다운받아서 바로 씁니다.** 
   - 윈도우 '개발자 모드' 덕분에 맥(macOS)처럼 자동으로 심볼릭 링크(거울)가 에러 없이 연결되므로, 플러그인 스킬도 즉시 연동됩니다. (별도 이동이나 JSON 수정 절대 불필요)
2. **내가 '새로운 커스텀 스킬'을 만들 때**
   - **Antigravity 환경**: 그냥 편하게 "스킬 만들어줘"라고 요청 (`GEMINI.md` 전역 규칙이 알아서 방어)
   - **Claude Code 터미널**: `/my-skill-creator` 명령어로 요청 (전용 스킬의 하드코딩 규칙이 알아서 방어)

이로써 플러그인 업데이트 시 스킬이 통째로 날아가는 데이터 유실 위험을 완전히 제거하면서도, 맥의 자동화된 편리함(심볼릭 링크)은 그대로 가져온 **궁극의 전문가용 세팅**이 마무리되었습니다.

### 🐛 버그 수정: ag-skills.ps1 심볼릭 링크 방식 오류

- **발견**: 기존 설치된 `ag-skills.ps1`이 `New-Item -ItemType SymbolicLink` 방식을 사용하고 있었음.
- **문제**: 이 방식은 개발자 모드와 무관하게 **관리자 권한을 별도로 요구**하여 에러 발생.
- **수정**: `cmd /c "mklink /D"` 방식으로 교체. 개발자 모드만 활성화되어 있으면 관리자 권한 없이 동작.

```powershell
# 수정 전 (버그)
New-Item -ItemType SymbolicLink -Path $target -Target $source | Out-Null

# 수정 후 (정상)
cmd /c "mklink /D `"$target`" `"$source`"" | Out-Null
```

> `terminal_guide_and_skill_script.md`의 설치 스크립트는 처음부터 올바른 방식으로 작성되어 있으나,
> 실제 설치된 `ag-skills.ps1` 파일은 구버전이었음. 재설치 시 위 스크립트 기준으로 진행할 것.

### 🗑️ 잔재 파일 정리: `~/.claude/skills/marketplace.json` 삭제

- **발견**: `C:\Users\{user}\.claude\skills\marketplace.json` 파일이 존재했음.
- **내용**: `perf-analyzer`, `project-ideator`가 `./skills/perf-analyzer` 경로로 등록되어 있었으나, 실제 파일 위치(`./perf-analyzer`)와 경로 불일치.
- **현재 영향**: 없음 (Claude Code는 디렉토리 직접 스캔으로 스킬을 인식하므로 이 파일은 무시됨).
- **잠재 위험**: Claude Code 내부 동작 변경 시 혼란 유발 가능.
