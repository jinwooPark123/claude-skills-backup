# Project Ideator

사용자가 프로젝트 아이디어를 원할 때 카테고리 선택 → 조건 확인 → 3개 아이디어 상세 구조화 순으로 진행한다.

---

## 워크플로우

### Step 1: 카테고리 선택

사용자가 이미 도메인을 명시했다면 스킵한다. 그렇지 않으면 아래 메뉴를 제시한다:

```
어떤 분야의 프로젝트 아이디어를 원하시나요?

1. IT / 앱 / 웹 서비스
2. AI / ML 활용 프로젝트
3. 비즈니스 / 스타트업 아이디어
4. 사이드 프로젝트 (소규모 / 개인)
5. 사회적 임팩트 / 비영리
6. 기타 (직접 입력)
```

### Step 2: 조건 확인 (선택적)

카테고리를 받은 후, 아래 두 가지를 **한 번에** 간단히 물어본다. 사용자가 "그냥 뽑아줘" 또는 빠른 응답을 원하면 바로 Step 3로 넘어간다.

- 선호하는 기술 스택이 있나요? (없으면 스킵)
- 특별한 제약 조건이나 타겟 사용자가 있나요? (없으면 스킵)

### Step 3: 아이디어 3개 생성

아이디어 3개를 아래 구조로 출력한다.

- **설명**: 15자 이내 한 줄 요약. 줄글 금지.
- **핵심 기능**: 글머리표 3~4개, 항목당 10자 이내 키워드 수준으로 짧게.
- **차별점**: 20자 이내 핵심 포인트.

---

## 출력 포맷

```markdown
## 💡 아이디어 1: [제목]
> [15자 이내 한 줄 설명]

| 항목 | 내용 |
|------|------|
| 기술 스택 | React, Node.js, PostgreSQL |
| 난이도 | 초급 / 중급 / 고급 |
| 기간 | X~Y주 |
| 차별점 | 20자 이내 핵심 포인트 |

**핵심 기능**
- 기능 키워드 A
- 기능 키워드 B
- 기능 키워드 C
```

---

## 💡 아이디어 2: [제목]
...
```

### Step 4: 후속 제안

3개 출력 후 마지막에 다음 문장을 덧붙인다:

> 더 구체화하고 싶은 아이디어가 있으면 번호를 알려주세요. 기술 설계, ERD, MVP 범위 정의 등을 도와드릴게요.

---

## 품질 가이드라인

- 아이디어 3개는 **난이도가 서로 다르게** (초급 1개, 중급 1개, 고급 1개) 구성한다.
- **설명**은 15자 이내. 줄글 절대 금지.
- **핵심 기능**은 글머리표로 3~4개, 항목당 키워드 수준으로 짧게 작성.
- **차별점**은 20자 이내. "편리하다" 같은 막연한 표현 지양.
- **기술 스택**은 선호 스택이 있으면 반영, 없으면 아이디어에 맞게 선정.
- **기간**은 혼자 작업하는 MVP 기준으로 현실적으로 산정한다.
- 한국어로 응답한다 (기술 용어는 원어 사용 가능).
